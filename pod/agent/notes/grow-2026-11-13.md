## The test: function-preserving MLP widening, then a short fine-tune

The model is d_model 192, 12 layers, d_mlp 768 (one width for all layers; it is one of the
config ints in the weights file, and `A_DMLP` already sets it in train_A_finetune, cooldown_A
and export_weights). `pysrc/prune_mlp.py` shows which state-dict keys carry the d_mlp dimension;
growth is its mirror image.

1. **Grow** P1c's checkpoints (the QAT one and the final one, `/workspace/pr_p1c/models/`) from
   768 to the new width in every layer.
   - New rows of mlp.up: random, at the size of the existing rows (same per-row statistics, and
     for any per-row/per-unit scale, bias, gate or norm entry use a typical existing value, e.g.
     the median). Check what else has the d_mlp dimension (act16 scales on mlp_down_in are per
     quantizer, not per unit, I believe; verify).
   - New columns of mlp.down: exactly zero, so the model computes the same function. Zero is a
     quantization level, so this holds under QAT too.
   - Optimizer state (Adam moments) for the new entries: zero.
2. **Dry-run check before any training:** Tier 0 of the grown final checkpoint must equal P1c's
   95,953,178 to within rounding (a few hundred bytes, not the usual +-8,000). If it does not,
   the growth is wrong: fix it, don't train.
3. **Fine-tune** with the gentle recipe that Tier 0 is validated for (A_LR 2.5e-7, P1c's mixer,
   A_MIXER=rich, CE 0.1, act16 on mlp_down_in + attn_out_in with frozen scales, 3+1 epochs).
   The gentle rate is too low for new units to learn anything, so give the NEW entries (the new
   up rows, new down columns and their per-unit parameters) their own, higher learning rate.
   Start from about the default recipe's rate (10x gentle) unless you see a reason for another
   value; keep the old weights at the gentle rate. State the value you used. If the down columns
   need a nonzero start to get any gradient through the quantizer (zero output and a
   straight-through estimator should still pass gradient, but check on a few steps that the new
   down weights actually move), say what you did.
4. **Score** with Tier 0 (set A_DMLP for it) and int bytes, against a CONTROL that gets exactly
   the same fine-tune with no new units. Do not compare against P1c or C2 directly: C1 showed
   that restarting training from P1c moves the score by itself.
   net = (Tier 0 grown - Tier 0 control) + 2 x (int bytes grown - int bytes control).
   Also report gain / cost = -(Tier 0 difference) / (2 x byte difference). Above 1 is a win.
