## What it is

`/workspace/sub/k3_src.tar.gz` = k2 (the faster 16-bit kernels) plus a multi-thread COMPRESS
mode, compiled in only with `-DCMIX_PIPE` and switched on at run time by the environment
variable `CMIX_TF_THREADS=N` (N worker threads; unset = the normal single-thread path).

How it works (comment block above `struct Predictor::TfPipe` in `src/predictor.cpp`): while
compressing, all bytes are known in advance and the transformer's output for a token depends
only on its own article piece. So the ppmd runs ahead of the coder (same thread, in bursts, up
to 400,000 tokens ahead; `CMIX_TF_AHEAD` changes that), each finished article piece goes to a
worker thread with its own transformer state (shared weights), and the coder picks up each
token's result in order. The online adaptation (dyn) and all other cmix models stay in the
coder's thread. Decompression cannot use it.

**The output must be BYTE-IDENTICAL to the single-thread compressor.** Laptop (Windows):
identical on enwik5 and enwik6 with 1, 3, 4 and 7 threads; enwik6 took 129 s single-thread and
74 s with 7 threads on a 4P+4E laptop, where the coder thread itself got slower from cache
contention. A longer check (enwik7 and 3 MB of the raw stream) is running on the laptop now;
I will add a line to this file if it fails.

Build notes:
- Add `-DCMIX_PIPE` to the defines of EVERY object, including the transformer objects
  (`cpp_infer/src/opt/attn.cpp` makes its scratch buffers per-thread only under that define;
  without it the threads corrupt each other and the output is wrong). Link with `-pthread`.
  Check with `grep`/`nm` or simply by the identity test below.
- Without `-DCMIX_PIPE` the source builds the ordinary k2 binary (same size as k2 on Windows).
  Do not use the pipe build for a submission.
- At the end of a run the program prints `tf pipeline: N threads, coder waited X s in Y waits`
  to stderr: X is how long the coder had to wait for the workers.
- Memory: about 1.3 GB for the look-ahead rings plus about 2 MB per thread. For a long run in
  this mode raise the ppmd memory cap so it does not remap constantly (the rings count toward
  RSS): a tune file with `ppmd_rss_mb 60000` via `CMIX_TUNE` (it does not change the output).
  Not needed for split-eval chunks.
